# 统一每日额度 ¥2，新用户注册赠 ¥10

| 项 | 值 |
|---|---|
| 日期 | 2026-11-07 |
| 状态 | **confirmed, to implement** |
| 依赖 | [`standard.md`](../standard.md) 第 4 节（额度与扣减顺序）、第 5 节（入账来源） |
| 影响 | `quota.dailyFreeMicro`、`quota.freeTiers`、新增 `signup.creditMicro`；注册流程；客户端额度显示 |

## 1. 问题

近 7 天（10-31 → 11-07）：**16,597 次调用、真实成本 ¥252.07、用户自付 ¥2.37**。

免费额度承担 99.3%。

**根因不是额度太高，是「每天重置」让试用期永不结束**：

```
第 1 天 额度 ¥3 → 试用
第 2 天 额度 ¥3 → 还在试用
```

按真实用量：101 个人天，中位数 **¥1.89/天**，最高 ¥9.28。一半的人每天花的钱不到额度——他们永远不会遇到「该付钱了」的那一刻。

## 2. 目标与范围

**目标**：把「体验」变成一个**有终点**的东西，同时让轻度使用继续保持免费。

**做法**：

| 项 | 现在 | 改成 |
|---|---|---|
| 每日免费额度 | 分档 ¥10 → ¥6 → ¥4 → ¥3 | **统一 ¥2**（取消分档） |
| 新用户注册 | 无 | **钱包 +¥10**（一次性，不可重置） |

**范围外**

- 不加上限透支（另做，见下文「顺序」）
- 不改结算倍率、扣减顺序、账本结构
- 不给存量用户补发 ¥10

## 3. 成本测算（基于真实用量）

| 日额度 | 7 天成本 | 相比现状 |
|---|---:|---:|
| 现状（分档） | ¥252.07 | — |
| **¥2（本设计）** | **¥146.99** | **省 42%** |
| ¥1 | ¥85.82 | 省 66% |

新用户赠送按每月 16 个、每人用满 ¥10 算：**¥160/月**。
日额度节省按同一周期算约 **¥420/月**。

**净节省约 ¥260/月**，且第一次出现「必须充值」的时刻。

## 4. 数据模型

**无 schema 变更。**

- 赠送走现有 `wallet_ledger`，`source = 'promotion'`（已有枚举，表示运营赠送）
- `externalRef = 'signup:<accountId>'`，靠 `(source, externalRef)` 唯一保证幂等——同一账号重复触发只入账一次

## 5. 流程

**注册时赠送**（`handleEmailVerify`，仅在账号**首次创建**时）

```
账号是新建的
  → grantCredit(accountId, signup.creditMicro, 'promotion', externalRef: 'signup:<id>')
```

存量账号不受影响：它们创建时这段逻辑不存在，也不会被补发。

**每日额度**：`quota.freeTiers` 置空 → `dailyAllowanceMicro` 直接返回 `quota.dailyFreeMicro`（¥2），不再分档。

## 6. 接口与配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| `quota.dailyFreeMicro` | `2000000`（¥2） | 从 ¥10 降到 ¥2 |
| `quota.freeTiers` | 空 | 取消分档 |
| `signup.creditMicro` | `10000000`（¥10） | 新账号注册赠送，设 0 可关闭 |

**客户端**：额度条只显示剩余比例，金额本身不暴露，所以不需要发版。但用户会明显感觉到每天能用的变少。

## 7. 风险

| 风险 | 说明 |
|---|---|
| **重度用户流失** | 28% 的人天超过 ¥3，他们第一次会遇到限制。可能充值，也可能走人 |
| **重注册套取 ¥10** | 没有删号功能，风险低；即使有，`signup:<id>` 幂等键也只对同一 id 生效 |
| **¥10 是真实成本** | 用户用掉就产生上游费用，不是虚拟数字。按每月 16 个新用户、用满计算约 ¥160/月 |
| **存量用户感觉被区别对待** | 如果他们知道新用户有 ¥10 而自己没有。目前没有对外公布，暂不处理 |

## 8. 上线顺序

```
1. 先部署网关（配置 + 赠送逻辑）—— 顺序不能反：客户端不受影响，但计费规则必须先在服务端生效
2. 观察 3 天：日额度 ¥2 下的实际成本、有多少人被挡
3. 再决定是否加透支上限
```

## 9. 验证

- 单元：`dailyAllowanceMicro` 在 `freeTiers` 为空时返回 `dailyFreeMicro`
- 单元：同一账号重复赠送只入账一次
- 集成：新账号注册后钱包为 ¥10；存量账号注册路径不触发赠送
- 真实：注册一个临时账号，确认 `wallet_ledger` 有 `promotion` 行、金额 ¥10
