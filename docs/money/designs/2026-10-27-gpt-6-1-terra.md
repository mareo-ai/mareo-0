|---|---|

| 状态 | **confirmed, to implement** |

## 1. 目标与范围

**目标**：给用户一个**日常编码任务最划算**的付费选项。Terra 的输入/输出价格是 Sol 的一半，OpenAI 称其在同等推理强度下比 Sol/Astra 快三倍以上。

**范围外**

- 不改免费额度策略：Terra 属于 OpenAI 上游，继续**不占免费额度**（`FREE_ALLOWANCE_EXCLUDED`）。
- 不改结算倍率、扣款顺序、账本结构。
- 不做模型自动路由（按任务难度自动选 Sol/Terra）——那需要独立设计。
- 不基于厂商基准做宣传承诺：Terminal-Bench 数字来自 OpenAI 自评，我们没有独立验证。

## 2. 价格（厂商公布，USD / 1M tokens）

| 模型 | 缓存读 | 输入 | 输出 | >272K 输入 |
|---|---:|---:|---:|---|
| **GPT-6.1 Terra** | **$0.05** | **$1.00** | **$5.00** | $0.10 / $2.00 / $7.50 |
| GPT-6.1 Sol（已接入） | $0.20 | $2.00 | $10.00 | $0.40 / $4.00 / $15.00 |
| GPT-6 Astra（已接入） | $1.00 | $10.00 | $50.00 | $2.00 / $20.00 / $75.00 |

来源：[LiteLLM 的定价说明](https://docs.litellm.ai/blog/gpt-6-1-terra)（逐项列出官方价格与 272K 阶梯）。

## 3. 结算算术与边界

**已实现的规则直接适用**，本设计不新增算法：

```
actualMicro = ceil( USD 价格 × token 数 / 1e6 × FX率 × 1e6 )
billableMicro = ceil( actualMicro × 结算倍率 )
```

**长上下文**：输入超过 `LONG_CONTEXT_TOKENS`（272,000）时**整单**按 2× 输入价、1.5× 输出价计费。

对 Terra 恰好等于官方阶梯：

| 项 | 常规 | 规则算出 | 官方 |
|---|---:|---:|---:|
| 缓存读 | $0.05 | ×2 = $0.10 | $0.10 ✓ |
| 输入 | $1.00 | ×2 = $2.00 | $2.00 ✓ |
| 输出 | $5.00 | ×1.5 = $7.50 | $7.50 ✓ |

**无需为 Terra 增加任何特殊分支。**

### 必须在测试里固定的边界

1. 一次 100K 输入的请求按常规价（不是长上下文价）
2. 一次 300K 输入的请求，**整单**按 2× / 1.5×（不是只对超出部分）
3. 缓存命中的 token 用 `cacheHit` 价，不落入 `cacheMiss`

## 4. 数据模型

**无变化**。`usage` 表已存 `provider`、`fxRate`、`actualMicro` 等字段，`model` 列存模型 id，新模型不需要迁移。

历史行不受影响：Terra 的请求只从接入那天开始出现。

## 5. 流程

无变化。定价在请求结束时计算并落库，已经在跑。

## 6. 接口与配置

| 位置 | 改动 |
|---|---|
| `server/src/pricing.ts` | `OPENAI_USD_PRICES` 加 `'gpt-6.1-terra': { cacheHit: 0.05, cacheMiss: 1, output: 5 }` |
| `src/model-catalog.ts` | 新增模型条目 `Mareo-O-61-Terra`，`contextWindow: 1050000`、`maxTokens: 128000`、`input: [text, image]` |
| `src/model-catalog.ts` | `compaction-basic` 的 `modelPolicies` 增加一条，保留 40000 token |
| 网关环境 | `PRICING_FX_RATE` 不变（默认 7） |

**模型 id**：`gpt-6.1-terra`（沿用厂商 id，带点）。
**显示名**：`Mareo-O-61-Terra`（按 `Mareo-[公司首字母]-[去前缀型号]`，点号在显示名里去掉以免和分隔符混淆）。

**老客户端**：模型列表由客户端打包，旧版本看不到新模型，但不需要任何兼容处理——它们发的请求里不会出现 `gpt-6.1-terra`。

## 7. 客户端影响

**需要发版**。用户在下拉里会看到第三个 Mareo-O 模型。

描述文案（草稿）：`日常编码与办公任务，比 Sol 便宜一半、快三倍；不占免费额度`。

## 8. 报表

无新口径。`usage.model = 'gpt-6.1-terra'` 的行会自动出现在现有的按模型统计里，成本和毛利按同一公式算出。

## 9. 上线顺序

1. 网关：加价格 → 部署（先于客户端，否则客户端发来的 Terra 请求算不出价）
2. 客户端：加模型条目 → 发版
3. 观察一周：Terra 的请求量、平均单请求成本、是否有人因为它第一次充值

## 10. 验证

- 单元：`costOf('gpt-6.1-terra', …)` 在常规与长上下文两种输入下的金额
- 集成：真实调用一次 `gpt-6.1-terra`，确认 `usage` 行里 provider=openai、金额>0、`paidFromFreeMicro = 0`（不占免费额度）
- 回归：Sol/Astra 的价格不变

## 11. 风险与取舍

| 风险 | 说明 |
|---|---|
| **没人用** | 它是付费模型，而目前没有任何普通用户充过钱。最可能的结果是它安静地待在下拉里 |
| **性能数字来自厂商** | Terminal-Bench 50.3% 是 OpenAI 自评，我们没有独立跑过。文案里不写数字，只写"便宜一半、快三倍"（后者也是厂商说法，措辞上弱化） |
| **免费额度边界** | 继续不覆盖，成本可控；代价是用户必须先充值才能试。这可能是它没人用的原因之一 |
| **价格可能再变** | 厂商调价时改一行 `OPENAI_USD_PRICES`，不用发版（网关侧） |
