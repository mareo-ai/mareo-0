# Mareo 金额口径规范

> 这是 Mareo 一切与钱有关的口径的**唯一权威来源**。代码、报表、文案、后台配置与本文冲突时以本文为准。
> 要改口径：先改这里 → 在文末「变更记录」留痕 → 再改依赖它的代码。**不允许悄悄改已上线的口径。**

## 1. 单位

| 场景 | 单位 |
|---|---|
| 面向用户（界面、提示、账单） | 人民币**元**，显示两位小数 |
| 存储与计算 | **微元**（1 元 = 1_000_000 微元），整数运算 |
| 换算 | 只允许出现在边界（渲染文案、读运营报表）；**禁止用浮点累加金额** |

## 2. 真实成本 actual_model_cost

- 定义：我们向 DeepSeek 支付的成本，按**上游返回的 usage token** 计算（不按字节、不按次数）。
- 唯一实现：`server/src/pricing.ts`（含高峰时段翻倍、缓存命中/未命中/输出三档单价）。**任何其它地方不得自算单价。**
- 只有 `status = 200` 且拿到 provider usage 的调用才产生真实成本；失败/中断的请求不计价（缺 usage 的行如实记为缺失）。

## 3. 销售结算 billable_cost

- `billable_cost = ceil(actual_model_cost × 该模型的销售倍率)`，**按微元向上取整**。
- 销售倍率**按模型分别配置**，当前所有模型都是 **1.3**：

| 配置项 | 作用 |
|---|---|
| `billing.settlementRate` | 默认倍率，用于没有单独配置的模型（当前 `1.3`） |
| `billing.modelRates` | 按模型的覆盖表，格式 `模型名:倍率`，逗号分隔，例：`deepseek-v4-pro:1.5,deepseek-flash:1.3` |

- 覆盖表的键**必须是 `pricing.ts` 价目表里存在的模型名**；拼错的键要被**拒绝**（不允许静默回落到默认倍率，否则等于悄悄改了价）。
- `margin = billable − actual`，**逐笔记录**，所以报表既能看总毛利，也能按模型拆分；改某个模型的倍率**只影响之后的请求**，历史行保持当时结算的倍率（每行的 `actualMicro` 与 `billableMicro` 都在，事后可反推当时用的倍率）。
- 用户侧**不得出现** token 数、上游单价、销售倍率、毛利。
- 每日免费额度只以**剩余比例**呈现，不显示金额——额度是可调的运营参数，显示金额等于把它公布出去；也不能显示「可用合计」，否则用合计减余额就能反推出免费额度。Wallet 是用户自己的钱，**余额如实显示到分**（含透支后的负数）。

## 4. 两个桶与扣减顺序

| 桶 | 是否重置 | 是否进账本 | 来源 |
|---|---|---|---|
| 每日免费额度 | 北京日 0 点重置 | 否 | 配置 `quota.dailyFreeMicro`（当前 ¥10/天） |
| Mareo Wallet | 不清零、不过期 | 是 | 唯一来源是账本（`grantCredit`） |

- 扣减顺序：**先每日免费额度，后 Wallet**。一笔请求可以跨桶（免费部分付不完的由 Wallet 付）。
- 闸门：**免费剩余 > 0 或 Wallet 余额 > 0** 即放行；两者都耗尽才拒绝。
- **允许最后一笔透支**：放行的那一笔可能把 Wallet 扣成负数；余额 ≤ 0 且免费已用完时拒绝新的调用。
- 计费范围：`chat`、`title`、`search` 三类调用**全部计入**用户结算。

## 5. 入账 grantCredit

- 唯一入口：`grantCredit(userId, amountMicro, source, { externalRef, channel })`。
- 来源枚举（封闭集合，新增须改本节并留痕）：

| source | 含义 | externalRef | channel |
|---|---|---|---|
| `purchase` | 用户充值 | 订单号 | 支付渠道 |
| `invite` | 邀请奖励 | 邀请记录 id | — |
| `reward_ad` | 看广告奖励 | 任务 id | — |
| `promotion` | 运营赠送 | 运营单号 | — |
| `affiliate` | 联盟/渠道分成 | 渠道单号 | — |
| `manual` | 人工调整 | 可选 | — |

- 入账**必须幂等**：`(source, externalRef)` 唯一，重复调用返回已有条目、不重复加钱。
- **充值金额是负债（用户未来可消费的余额），不是收入。**

## 6. 账本 wallet_ledger

追加型，只写不改。字段语义：

| 列 | 语义 |
|---|---|
| `userId` | 账号 |
| `type` | `credit`（入账）/ `debit`（消耗） |
| `amountMicro` | 恒为正，方向由 `type` 决定 |
| `source` | 入账用第 5 节的枚举；消耗固定为 `model_usage` |
| `balanceAfterMicro` | 写这条之后的余额，**可为负**（透支） |
| `relatedRequestId` | 消耗时 = `usage.id`，用于逐笔追溯 |
| `externalRef` / `channel` | 幂等键与渠道（见第 5 节） |
| `createdAt` | ISO 时间 |

- **余额 = 该用户最后一条的 `balanceAfterMicro`**；不维护可变计数器。
- 读+写必须在同一事务内完成（单进程单写者，天然串行）。

## 7. 报表定义（唯一口径）

| 数字 | 定义 |
|---|---|
| 充值金额 | `SUM(amountMicro) WHERE source='purchase'`（附笔数） |
| 奖励额度 | 按 `invite / reward_ad / promotion / affiliate / manual` 细分 |
| 已消耗额度 | `SUM(amountMicro) WHERE source='model_usage'`，即**用户结算成本** |
| Wallet 余额 | 全站 `balanceAfterMicro` 之和（= 负债） |
| 真实模型成本 | `SUM(usage.actualMicro)` |
| 结算成本 | `SUM(usage.billableMicro)` |
| 毛利 | 结算成本 − 真实模型成本 |
| 免费额度真实成本 | `SUM(actual × paidFromFree / billable)`，单列为**获客成本**，不计入 COGS |
| 额度影响（影子估算） | 按每笔**结算成本**累计：免费额度就是按结算成本扣的，这样估算与真实拦截口径一致。计费上线前的历史行没有结算成本，按真实成本计入 |
| 下单数 / 支付成功数 | 当日创建的支付订单数 / 当日 `status='paid'` 的订单数（按北京日归属） |
| 支付成功率 | `paid / (paid + failed + cancelled)`；`pending` 不计入分母 |
| 渠道占比 | 当日已支付订单的金额与笔数按 `provider` 分组 |
| 充值人数 | 当日已支付订单的 distinct `userId` |
| 平均到账时长 | `paidAt − createdAt` 的均值与 P90（只统计已支付订单） |
| pending 积压 | 当前仍为 `pending` 且未过期的订单数 |

报表固定打印三句口径说明：

1. **充值 ≠ 收入**：充值是可消费余额（负债），只有被消耗才形成收入。
2. **毛利只按已消耗口径计算**，不按充值口径。
3. **免费额度消耗不产生收入，但产生成本**（获客成本）。

- 与上游账单对账只用于校验**真实模型成本**；结算侧没有外部账单，以内部账本为准。

## 8. 充值（支付订单）

- **支付成功是唯一入账依据**：只有服务端验签通过的支付回调，或服务端主动查单得到的"已支付"，才可把订单置为 `paid` 并调用 `grantCredit`。客户端显示的"支付成功"不产生任何账务影响。
- **金额 1:1**：用户实付多少就入账多少（单位为微元，`1 分 = 10 000 微元`）；换算只允许出现在支付边界，禁止浮点累加。
- **订单状态**：`pending → paid | failed | cancelled`，`paid → refunded`。收到支付成功确认时，`pending / cancelled / failed` 都可转 `paid`（二维码过期不等于收不到钱），`paid / refunded` 必须拒绝（重复回调或已冲正）。
- **幂等**：状态机（只有非 `paid` 能转 `paid`）与账本唯一索引 `(source, externalRef)` 双层保证，且与入账在同一事务内；重复回调不得重复加钱。
- 充值只是 Wallet 的来源之一，**支付系统与 Wallet 解耦**：支付侧只负责"确认收钱"，入账一律走 `grantCredit(source='purchase', externalRef=orderId, channel=支付渠道)`。
- 第一版不做退款与赠送：不做自助退款流程，订单表保留 `refunded` 状态以备人工处理；充值金额与入账金额恒等。
