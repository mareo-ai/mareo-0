# 注册与使用的滥用防护

一句话：**一次性邮箱注册一个账号，就白拿一天的免费额度**。12 个这样的账号在一个月里消耗了大部分免费额度。这份文档记录挡在哪几层、为什么不挡更多。

## 威胁模型（来自生产数据）

2026-10-10 与 10-14 两天集中注册的一批账号：

- 邮箱来自一次性邮箱服务（`deepyinc.com`、`inctart.com`、`swagpapa.com`、`123mails.org`、`besttempmail.com`、`mowan666.com`）
- 注册后立刻高强度使用，白天时段，日均 100–350 次调用
- 30 天消耗 ¥897 真实成本，几乎全部由免费额度承担

注意：他们的使用时段符合人类作息，不是 24 小时脚本。**他们要的是额度，不是攻击系统**。

## 四层防护

| 层 | 措施 | 拦截时机 |
|---|---|---|
| **1. 发送验证码** | 一次性邮箱域名黑名单 | `POST /auth/email/send` 直接 400，不发信 |
| **2. 登录** | 同上（黑名单可能后加） | `POST /auth/email/verify` 400 |
| **3. 账号识别** | 邮箱规范化：`+tag` 与 Gmail 的点号视为同一邮箱 | 注册时按规范化形式查重，复用已有账号 |
| **4. 观察** | 同域名 1 小时 ≥5 个新账号 → 记一条日志 | 只告警，不拒绝 |

### 为什么第三层重要

没有它，`a+1@gmail.com`、`a+2@gmail.com`、`a.b@gmail.com` 是三个账号，各自带一份每日额度。规范化之后它们指向同一个账号。

### 为什么第四层只告警

163.com、qq.com 是主流邮箱。一条规则误伤一个真实用户的代价，大于放过几个薅羊毛的。先观察，再决定是否收紧。

## 黑名单怎么维护

配置项 `auth.blockedEmailDomains`（逗号分隔，子域名一并拦截）：

```sh
docker compose exec -T gateway node dist/src/config-cli.js set auth.blockedEmailDomains "a.com,b.com,..."
```

默认值包含已发现的 6 个域名 + 12 个常见的一次性邮箱服务。

## 明确不做

| 不做 | 原因 |
|---|---|
| IP 限流 / IP 黑名单 | 隐私说明承诺服务端不落库 IP |
| 设备指纹 | 同上 |
| 行为风控模型 | 成本高、误伤大，当前规模不需要 |
| 封禁已注册的滥用账号 | 会引来申诉；靠额度分档（重度 → ¥3）自然压成本更平和 |

## 已知限制

- 黑名单只防未来：已经注册的账号不受影响
- 一次性邮箱服务域名会不断新增，靠运营补充，不追求穷举
- 规范化只在邮箱维度生效：一个人用两个不同邮箱注册，仍会被视为两个账号
