# 产品页面设计原则（Mareo）

这份文档是 Mareo 运营页面的**取向标准**：它决定"什么该出现、什么该克制"，与
[`web-interface-guidelines.md`](./web-interface-guidelines.md)（逐条可核对的工程规则）配套使用。

- **取向**由本文决定：先想清楚页面为谁、回答什么问题，再决定放什么。
- **执行**由规则清单兜底：改完页面后逐条自查，只报销到具体位置的违规。

## 目标

面向 SaaS / AI 产品 / 运营后台 / 数据看板。设计目标不是"视觉炫酷"，而是：

1. 信息层级清晰
2. 用户能快速找到最重要的信息
3. 克制、现代、专业
4. 避免模板感、过度装饰和无意义视觉元素
5. 优先服务真实产品决策和操作效率

## 核心原则

- **先理解页面目标，再设计布局**，不要先套模板。
- 每个页面有一个明确的主任务，视觉层级围绕主任务组织。
- 顶部优先放最重要的结论、状态或 KPI。
- 次要信息下沉，不要所有数据同等强调。
- 避免大量同样大小的卡片平铺。
- 不要为了"丰富"增加没有决策价值的图表；图表只在能明显提升理解时使用。
- 数据页优先回答"发生了什么、为什么、下一步看什么"。
- 避免大面积渐变、霓虹色、玻璃拟态、过度阴影。
- 默认中性色、清晰边界、合理留白、简洁排版。
- 字号、字重、间距必须有明确层级。
- 数字 KPI 突出，说明文字弱化。
- 不要显得拥挤；不要为了"高级感"牺牲可读性。
- 表格适合精确比较，图表适合趋势和结构，不滥用。
- 异常/风险/增长/下降用**明确但克制**的状态色。
- 所有交互状态都要考虑：loading、empty、error、disabled、hover、selected。

## Dashboard 的五层结构

1. **核心状态**：10 秒内知道当前业务状态
2. **趋势**：关键指标最近的变化，而不只是累计值
3. **漏斗 / 转化**：用户从进入到关键目标之间的损耗
4. **分布与结构**：用户类型、任务类型、平台分布等
5. **明细**：表格、账号、订单、错误记录

**技术健康指标与业务指标必须分离**：CEO / 运营首页不被日志、延迟、版本号淹没；工程指标放进独立的 Health 页。

## 数据诚实性（Mareo 的硬规则）

这些不是审美问题，是"不能骗自己"的问题：

- **不同口径的数据不放在同一条链路里**。周窗口的计数不能和累计值算转化率。
- **分母不成立就不给百分比**；分母 < 5 时标注"样本小"。
- **数据缺失不画成 0**：没有采集到的环节写"缺数据"，不要用 0 让人误读。
- **未到期的指标显示 `—`**（例如今天刚来的 cohort 没有 D1）。
- **不编造收入**：没有数据来源的指标（广告、CPS）就不出现。
- **充值 ≠ 收入**：先成为 Wallet 余额，被消费时才形成收入。

## 重构已有页面的顺序

1. 先读现有代码和数据结构
2. 保留已有有效功能，不为视觉效果重写业务逻辑
3. 优先改信息架构、布局、层级、间距、组件一致性
4. 复用已有设计系统（颜色、字体、圆角、间距）
5. 信息太多时**优先删减和重新分组**，而不是加组件

## 最终的观感

简洁、克制、清晰、专业、可信、有产品感。

而不是：炫技、模板化、花哨、"AI 生成感"。
