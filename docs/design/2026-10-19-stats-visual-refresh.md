# 三个运营页面的视觉重构

- 日期：2026-10-19
- 状态：confirmed, to implement
- 依赖：[`../money/standard.md`](../money/standard.md)、[`product-design-principles.md`](./product-design-principles.md)、[`themes/dashboard.md`](./themes/dashboard.md)、[`web-interface-guidelines.md`](./web-interface-guidelines.md)
- 影响：`/stats/`、`/stats/users/`、`/stats/health/` 的 HTML 展示；不改变数据采集、查询或资金行为。
- 审阅状态：文档已于 2026-10-19 提交（87e079f），用户确认「没问题，继续吧」，开始实现。
- 实施状态：代码已完成并验证，待代码审阅、合并与单独批准部署；生产尚未变更。

## 1. 目标与边界

保留现有内容，将纵向堆叠的报表调整为主次清晰的运营工作台。优化分组、布局、字阶、表格与状态表达，不删指标、不添加运营结论。

不做：新指标、统计口径调整、查询优化、数据修复、计价与扣费修改、支付与钱包修改、刷新周期调整、访问权限调整、客户端发版、生产部署。官网 `website/` 不在本任务范围。

## 2. 视觉方案

### 公共框架

- 延续中性底色、白色面板、蓝色强调与系统深色模式，不改成宣传页。
- 保留吸顶顶栏与三个页面入口，不新增侧栏；当前页高亮，键盘焦点清晰。
- 加强页面标题、分区标题、重点数值与辅助说明之间的层级。
- 统一面板间距、圆角、表格密度和状态标签。颜色辅助文字，不作为唯一信息载体。
- 桌面端采用有主次的组合布局，手机端单列；宽表格仅在自己的容器内横向滚动。
- 不添加粒子、持续动画、数字滚动、外部字体、外部脚本或新依赖。

### 经营看板

- 顶部保留系统状态，随后为 DAU、新增激活、回访、D7 留存主指标区，Session 与请求数作为辅助信息。
- 桌面端增长与商业表现并排。访问次数与账号转化明确分组，不画成同一条漏斗。
- 商业区将现金相关信息与结算、余额信息分组，保留各自原标签、原数值、原单位、原解释与时间范围；不以布局暗示充值等于收入。
- 任务分布保留现有横向条形与数据，提升标签和数值的对齐。

### 用户与留存

- DAU / WAU / MAU 为顶部概览；留存表为主要阅读区域。
- 留存格使用低饱和单色深浅辅助比较，仍显示原百分比。未到期的 `—` 保持无填充，不等同于 0%；保留小样本标记。
- 使用深度按使用频率与成本分布分组，字段、顺序含义与计算保持不变。
- 重度用户保留宽表格，付费状态使用文字标签，负余额用警示色且保留负号，不增加身份字段。

### 工程健康

- 优先展示系统状态以及已有的启动成功率、模型成功率、异常退出、延迟数据，不引入新的告警阈值。
- 请求结果与既有趋势图组合布局，提高趋势图可读高度，不改变序列、坐标含义或总数。
- 登录、用量异常、版本与平台等现有内容继续完整展示。

## 3. 金额算术与边界验收

资金计算完全复用现有实现，权威规则只引用 `standard.md` 第 1–8 节；不在本文件另立价格、取整、扣减或报表定义。以下仅为验证显示未改变的输入输出样例，不是新规则：

- 输入 `actualMicro=1000000`、`billableMicro=1300000`、`marginMicro=300000`：仍显示 `¥1.00`、`¥1.30`、`¥0.30`，不从已格式化字符串重新计算。
- 输入 `rechargeMicro=0`、`cashNetMicro=-1000000`、`costRecovery=0`：仍显示 `¥0.00`、`-¥1.00`、`0.0%`，负值不能只通过颜色表示。
- 输入 `costRecovery=undefined`：仍显示 `—`，不能改成 `0%`。
- 输入 `walletBalanceMicro=-1230000`：仍显示 `-¥1.23`；零余额显示 `¥0.00`。
- 输入 1 微元：维持既有两位小数显示结果 `¥0.00`，不改变底层值或新增精度策略。
- 很大的金额不截断，不改为缩写；缺失、零、负数必须可区分。
- 跨桶、最后一笔透支、结算取整沿用现有钱包与计费测试；视觉代码不得介入这些链路。

## 4. 数据模型与历史数据

无表、列、索引或迁移变更。历史记录不修改，不补算。沿用 `Metrics` 与 `UserMetrics`，展示层仅消费已有值。

## 5. 业务流程

模型调用前校验、调用后结算、入账、每日重置均不修改，沿用 `standard.md` 与现有测试。

报表流程保持：现有查询收集指标 → 页面渲染函数生成静态 HTML → 现有脚本临时文件生成成功后替换目标文件。视觉重构只作用于中间渲染步骤，失败时保留旧页的发布行为不变。

## 6. 接口与配置

保持 `ceo|users|health` 页面标识、URL、命令入口、配置默认值、刷新频率与 Basic Auth。无 API 响应变更，无客户端兼容层。静态页面继续自包含且无外部资源请求。

## 7. 客户端影响

仅运营人员看到网页布局变化；桌面用户的金额、额度、充值体验均不变。不需要桌面客户端发布。

## 8. 报表输出约束

所有金额定义以 `standard.md` 为准，当前渲染字段与注释全部保留。不得将重排版式演变为重算财务数字，不改变今日与近 7 天的范围，也不将缺失数据显示为零。

对同一输入，重构前后的指标标签、数值、单位、覆盖率、解释与明细应一致。若验证发现当前报表与权威口径冲突，单独提交问题并重新确认，不在本视觉任务内悄悄修正。

## 11. 风险与取舍

- 财务指标分组可能造成新的含义暗示：保留原标签与说明，禁止把充值称作收入。
- 留存颜色可能放大小样本差异：保留样本标记、数值与缺失状态，颜色不替代判断。
- 大屏双列可能挤压内容：设置响应式单列回退，宽表格不强行压缩。
- 文档中的旧状态不一定等于最新生产状态：不据此修改数据或权限。
- 当前公共页脚的隐私表述与用户明细是否一致，属于内容审查问题；此次不扩展到数据披露策略变更。
